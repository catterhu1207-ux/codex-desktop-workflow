# Desktop workflow maintenance

## Continue the authorized task

Read the latest terminal records and exact input identities before resuming. Carry diagnosis, the smallest correction, affected checks, actual installer/launcher consumers and eligible closeout through without asking for a generic “continue” at each internal stage. Preserve the active application. Request only a missing necessary fact, new authorization or an agreed resource-resume decision. A required natural restart is one concrete pending action, not permission to terminate the user's app or create background jobs.

Keep a compact checkpoint: objective, authorized destinations/actions, package/artifact identities, completed evidence, remaining gates, owned-process closure, retained inputs and next action. Reconcile uncertain writes before retrying. Prior receipts do not create authorization.

## Bound space and repeated work

Inventory existing work before allocation. Reuse one temporary build root, one isolated test slot and one candidate; multiple scenarios have distinct run identities, not indefinite full application copies. Additional complete copies require explicit authorization. Use verified official inputs read-only and rehearse transformed entries before copying or compiling.

Assess backend reuse from actual code, upstream commit, patch, lockfile, effective toolchain/build recipe and all migration checksums. A version string or signature-only difference is insufficient. Preserve public-source build provenance; private binaries cannot substitute for public builds.

Reuse passed evidence only when all its dependencies are unchanged. A diagnostic exception is an error to explain, not “candidate absent” and permission to rebuild. Validate immutable package/backend inputs ahead of heavy history scans and checkpoint only fully verified task results. Retire authorized disposable caches after each closed stage; retain necessary fixtures and unique recovery evidence. Prove paths, links, file identity, occupancy and recovery before deletion.

## Check producers and real consumers

Compare helper, schema, strategy, proof and version identities before data mutation. Execute the actual receiver in the shortcut's real host as well as the helper. An error must identify the mismatched field; two equal helper versions do not rule out a different history-proof version.

Audit complete relevant history inventories, including native compressed files. Classify a new unsent draft, materialized history, valid projected continuation and genuine missing/corrupt history separately. A partial tool-output record is removable only with strict adjacent complete-record identity, ordinal, timestamp, byte-prefix and dependent-offset proof. Preserve the original and verify projection payloads/cursors transactionally. Never generalize a historical fragment length or suppress unrelated errors.

Trace native settings through their real scope reader to a mounted sidebar. Trace request state through ordinary/pinned/local/SSH rows. Preserve current update-time ordering, manual ordering, model bindings, orange user-action requests, yellow pending implementation, Work, drag/drop and pagination according to the target's exact contract.

## Diagnose timing from actual evidence

Read the entire preserved same-run renderer log before changing a timeout. Separate route, module load, feature execution and observation budgets using a validated awake clock. Reserve full observation within the overall cap. A populated-profile proof can arrive after an overly short deadline; a late complete proof establishes that diagnosis, not a successful observation.

The October 2026 incident completed all 23 required renderer proofs in 49.154 seconds after module load, after a 30-second limit had rejected it. The scoped correction used up to 90 awake seconds while reserving 60 seconds for observation. These values and feature counts are case evidence, not defaults for every version.

Feed actual signed logs to the production parser. Reject wrong version/artifact/run/PID/transport, missing or failed features, stale logs and bypass/traversal routes. An audited timing-only rejection can become eligible for a fresh run after matching source, binary and backend identity checks. Preserve the failed terminal; the new run needs fresh complete proof and observation.

## Report independent outcomes

Distinguish local preparation, first genuine launch, lifecycle completion, public source update, installable release and cleanup. Complete installer creation, final assets, independent public build, Actions, anonymous download and installation/runtime checks remain publication gates. A matching source unavailable for an older target stays a named blocker; it neither authorizes silently changing targets nor blocks unrelated qualified cleanup.

Archive only authorized sanitized recovery materials. Credentials, accounts and real chat content/databases stay out of public and private archives. Independently restore and verify an archive before deleting originals. Preserve running/installed components and required rollback. Push unique task-local Git changes and verify remote recovery before retiring redundant checkouts.

## Resource refusal and public UI language

Identify the actual failed stage before rebuilding. A high handle count in an unrelated process is diagnostic; fixed counts alone do not establish Windows resource exhaustion. Use an applicable OS resource signal or demonstrated failure for a blocking policy, preserve unreadable-sampling rejection, and do not restart unrelated services as a launcher workaround. A passing helper check is distinct from a fresh genuine startup.

Trace transformed output before declaring a private dependency: private-manager strings may be original-byte matching templates replaced by a later exact transformation. Verify the complete transformation chain and packaged result.

For an English public release, check installer and launcher prompts, added renderer labels, the actual native language default and mounted controls. Preserve protocol identities, user text and existing language choices. A new artifact identifier must match every producer and production parser before expensive runtime checks. Old release evidence stays historical; record new results under the new identity.

For first-message failures, monitor/launcher disagreement and revision-specific consumers, see [first-send and monitor lessons](firstsend-and-monitor.md).

For activity time after restart, native SSH identity and Windows resource bytes, see [native activity ordering and acceptance](native-time-and-ui-evidence.md).

## Minimized windows and independent build phases

Require fresh proof from the actual primary renderer. When feature checks finish while a window is hidden, preserve the terminal result and publish it again after visibility or focus is restored, together with its original module identity. A retained failure stays a failure. Test hiding and restoring the native application; do not treat a background page or a fabricated visible flag as equivalent.

Before starting a native executable, check its actual Windows integrity label and its inherited launch environment. An executable blocked before JavaScript starts requires a location or launch-context diagnosis. Move only the owned candidate to a verified ordinary application directory when authorized; retain exact bytes and do not weaken machine security or close unrelated applications.

Budget debug tests, incremental outputs and release compilation separately. Preserve a module-test checkpoint only after the complete test summary and a second source-input check. Bind it to source, patch, recipe, lockfile, toolchain, environment and test-log digest. A supervisor exit code alone is insufficient. Reuse a checkpoint only while those bindings still match. Retire completed debug dependencies only after their job is empty and the next phase does not require them; keep per-volume reserves.

Cold-reopen checks bind a chat's canonical ID and host before comparing display text. A native UI may show a cleaned message marker while storage retains its attachment preamble. Normalize only a recognized Windows extended-path prefix, then prove containment and the same file identity. Keep raw history bytes unchanged and retain path-escape rejection.

A negative proof case passes only when the production parser executes successfully and rejects the intended changed input. A parser import or runtime error is a failed test. When visibility recovery republishes a completed run, select one actual module/terminal pair and preserve its run identity. Use the foreground launcher's exact host, then check wrong identity, PID, schema, transport, stale input and incomplete feature evidence independently.
