# Native activity ordering and acceptance

## Activity time survives a restart

Desktop 26.1016.6573.0 can update stored `updated_at` when a chat is resumed without a new message. Its native `recencyAt` is the ordering value. The adapter keeps the verified `recencyAt ?? updatedAt` producer and refreshes the list consumers that previously held an outdated snapshot.

Regression checks must prove that a new reply moves a chat forward and that reading an old chat does not promote it after restart. Compare entries inside the same activity section, preserve native ties and verify manual pin order separately.

## Verify the native route and selected setting

Optimistic row IDs do not identify the execution host. Check the separate host identity, selected project, actual backend and saved synthetic history. For model controls, inspect the native selected-effort value; one button can contain text for every animated effort label.

A first-send check starts from the native new-chat screen with a verified loopback provider. Project selection and file-drop setup must pass before sending. Record intent, then read the actual chat and its completed history. If a check fails after a send, read back the result before retrying. Derive titles from the fixture rather than assuming padding or excluding attachment preambles.

## Check publication and closed evidence

Preserve exact renderer-sidecar and delta bytes through Git checkout and wheel installation. Compare committed resources with their bound digests; automatic line-ending conversion can break a Windows download even when the original working copy succeeds.

After normal exit, copy the completed original logs for the production parser and verify the closed copy. Exercise the target parser's rejection cases as well as the valid log. A changed shutdown-log suffix is a reason to refresh the copy, not to invent another successful run.

Keep candidate runs serial, reuse the existing candidate and fixture slots, and distinguish source qualification, installation, public download verification and genuine daily launch.

## Version dispatch and PowerShell host encoding

Register a new version in both feature producers and installation consumers. Review the installer worker's pre-run input snapshot, post-exit log readback, qualification sealing and ordinary launch requirement together. A version missing from any one dispatcher can pass a low-level test yet fail its next ordinary launch. Test late renderer failure, changed inputs and a worker returning the wrong package version before distribution; the original manifest selects the gate.

Preserve the UTF-8 BOM of Windows PowerShell 5 scripts containing non-ASCII text. A Python copy written as UTF-8 without a BOM can break the native shortcut host's parser even when modern PowerShell accepts it. Parse and exercise staged functions in the actual shortcut host before installing the changes.

A launcher can recognize a new package at build time but still reject its cached pagination policy on the next start. Review exact-source selection, migration reference selection and cached history-policy dispatch as well as the renderer dispatcher. Execute the actual consumer block with the new policy, the previous policy and deliberately incompatible page-size/drain settings. Keep the original source and older branches unchanged.

Application exit and an empty Windows job are separate facts. Native UI controllers must enter their owned job before starting the candidate. After normal application exit, inspect the remaining job members, handle only verified auxiliary descendants, and record an empty job. Do not derive that claim only from the absence of the main process or app-server.
